# Bes3 购买决策与推广转化闭环重构方案 (Purchase Decision & Affiliate Conversion Plan)

**文档版本：** V1.1  
**文档状态：** Final Execution Plan with Implementation Gap Review  
**核心目标：** 将 Bes3 从“证据评测站”收敛为“购买决策引擎”，最大化降低用户购买决策难度，提高有效推广链接点击率，并让点击、页面和运营数据回流到商业闭环。

---

## 1. 结论

Bes3 当前底层能力已经足够强：商品同步、证据抽取、共识评分、价格价值、pSEO 页面、后台运营、风险治理和推广跳转都已具备基础。但公开站的产品表达仍偏“展示系统能力”，而不是“帮用户立刻完成购买决策”。

本轮优化的核心不是继续增加功能，而是进行产品收敛：

1. 减少公开站一级入口。
2. 降级工具型、研究型、数据型路径。
3. 将证据、价格、风险和推广链接统一压缩为一个可执行购买判断。
4. 让高意图用户从外部入口直接进入场景页、评论页、商品页、deal 页或对比页。
5. 让每个核心页面首屏回答：**现在买吗？为什么？点哪里？什么情况下别买？**

商业闭环定义为：

```text
高意图流量获取
  -> 场景/评论/商品/deal/对比落地页
  -> Purchase Decision 首屏决策
  -> /go/{productId} 推广跳转
  -> 点击与决策上下文记录
  -> 后台商业风险与修复队列
  -> 下一轮选品、证据、页面、链接优化
```

北极星指标：

```text
buy_ready_valid_affiliate_ctr =
  buy-ready 页面 /go 点击数 ÷ buy-ready 页面访问数
```

这比“总推广点击量”更准确，因为它只衡量证据、价格、链接和风险均达标页面上的有效点击。

## 2. 当前产品问题

### 2.1 公开入口过多

当前站点同时存在以下公开路径或概念：

- Categories
- Products / Evidence Matrix
- Deals / Best Value
- Reviews
- Compare
- Tools
- Shortlist
- Open Data
- Trust
- About
- Brands
- Directory
- Search
- Start
- Assistant
- Offers

其中部分路径已经是重定向壳，例如 `/assistant`、`/start`、`/search`、`/offers`、`/directory`。这说明产品形态已经演化，但信息架构没有彻底收敛。

用户的真实任务不是浏览这些功能，而是：

- 我这种需求该买哪款？
- 这款现在能买吗？
- 两款之间该选谁？
- 现在是不是好价？
- 这个推荐可信吗？

### 2.2 决策组件分散

系统已有多个决策相关组件或能力：

- Decision readiness
- Decision summary
- Decision reason
- Price value badge
- Timing decision
- Evidence matrix
- Shortlist
- Compare
- Sticky CTA
- Primary CTA

这些能力各自合理，但对用户来说会变成多个并列判断源。用户需要自己把证据、价格、风险、评分、CTA 拼成最终购买判断，决策成本仍然偏高。

### 2.3 页面叙事偏“研究”，不偏“购买”

商品页首屏目前更接近 `Evidence Report`。评论页更接近文章页。矩阵页更像数据库视图。Deal 页解释 value score 公式多于明确回答“现在要不要买”。

这会造成一个转化问题：Bes3 证明了自己可信，但没有足够强地告诉用户下一步该点哪里。

### 2.4 Review 评估与实现现状

外部 review 对本方案的核心判断是合理的：战略方向正确，架构基础已经存在，但最关键的 `purchaseDecision` 用户可见决策层尚未实现。

当前代码已有的基础能力：

| 已有能力 | 现状判断 |
| --- | --- |
| `buildCommerceDecisionReadiness()` | 已能评估普通商品的购买准备度、链接、价格、数据置信度。 |
| `buildEvidenceDecisionReadiness()` | 已能评估硬核证据商品的证据、价格、推广链接状态。 |
| `/go/{productId}` | 已有推广跳转、merchant click 记录和 fallback。 |
| `commercial-loop.ts` | 已有 affiliate sync、YouTube discovery、证据抽取、review 发布和推广路径。 |
| `decision-content.ts` | 已有结构化 buyer fit、风险、下一步文案基础。 |
| commission-blind audit | 已有不按佣金排序的审计基础。 |

当前关键缺口：

| 缺口 | 影响 |
| --- | --- |
| 缺少 `purchaseDecision` 派生层 | 现有 readiness 是后台信号，不是用户可见购买判断。 |
| 缺少 `PurchaseDecisionCard` | 商品页、评论页、deal 页、矩阵行 CTA 仍分散表达。 |
| Tracking 缺少 decision context | `/go` 点击无法完整回答“用户在什么决策状态下点击”。 |
| 导航未收敛 | `Evidence Matrix`、`Open Data` 等仍可能分散用户注意力。 |
| 后台缺少 Commercial Command Center | 运营无法直接围绕 buy-ready 和商业阻塞修复。 |

因此，本方案的实际实施状态应视为：

```text
策略与数据基础：已具备
页面与组件收敛：待实施
purchaseDecision 核心层：待实施
tracking context：待扩展
后台商业运营闭环：待实施
```

review 中建议的 A/B 测试、独立组件测试目录和联盟订单回传可以作为后续增强项，不应阻塞首期落地。首期必须先完成 `purchaseDecision` 与 `PurchaseDecisionCard`。

## 3. 产品收敛原则

### 3.1 少展示系统能力，多展示购买结论

公开站用户不需要理解 Bes3 有多少后台能力。用户需要看到：

- 当前最适合我的 1-3 个选择。
- 为什么这些选择可信。
- 现在是否值得买。
- 点哪里去买。
- 什么情况下不该买。

Evidence Graph、Taxonomy、Price Value、Risk Center、Open Data 都是支撑能力，不应抢占购买路径。

### 3.2 首屏只服务一个主动作

每个核心页面只能有一个视觉主 CTA。其他动作必须视觉降级。

示例：

| 页面状态 | 主动作 | 次动作 |
| --- | --- | --- |
| buy now | Check current price | View evidence |
| compare first | Compare alternatives | Save / shortlist |
| watch price | Track price drop | View merchant as secondary |
| skip | See safer pick | Read evidence |
| researching | Browse category | Request alert |
| link unavailable | See available alternatives | Read evidence |

### 3.3 复杂能力后置

完整证据矩阵、quote、source、FAQ、Open Data、methodology 等都必须保留，但它们不应该先于购买决策出现。

页面顺序应从：

```text
证据 -> 表格 -> 方法论 -> CTA
```

改为：

```text
购买判断 -> CTA -> 核心理由 -> 证据展开 -> 方法论
```

### 3.4 佣金中立不变

佣金率不参与推荐排序。商业化只影响 CTA 可用性和运营修复优先级：

- 有推广链接：可展示购买 CTA。
- 无推广链接：不能展示购买 CTA，但证据结论仍可保留。
- 佣金率高低：不改变推荐名次。

## 4. 信息架构调整

### 4.1 主导航

主导航收敛为 4 项：

| 导航 | 用户任务 |
| --- | --- |
| Best Picks | 找到当前最值得买的产品。 |
| Deals | 判断现在是不是好价。 |
| Reviews | 验证某个具体商品能不能买。 |
| Trust | 理解 Bes3 为什么可信、是否有利益冲突。 |

从主导航移除：

- Evidence Matrix
- Open Data
- Tools
- About

这些入口降级到 footer 或 Trust 页内部。

### 4.2 路由角色

| 路由 | 建议角色 |
| --- | --- |
| `/` | 导流与价值解释，不承担主要成交。 |
| `/categories` | Best Picks 总入口，按品类进入 Top 3 推荐。 |
| `/products` | All Tested Picks 或 SEO/内部列表，不作为主导航入口。 |
| `/deals` | 价格敏感入口，回答“现在是不是好价”。 |
| `/reviews` | 商品名搜索入口，回答“这款能不能买”。 |
| `/compare` | 二选一入口，必须给默认赢家。 |
| `/trust` | 方法论、FTC disclosure、开放数据、反佣金排序解释。 |
| `/tools` | 降级为辅助页面或并入 Trust/footer。 |
| `/shortlist` | 犹豫用户和回访用户路径，不抢首屏购买 CTA。 |
| `/assistant` | 如无真实助手能力，继续兼容跳转，不进入产品主叙事。 |
| `/start` | 继续兼容跳转到 Best Picks。 |
| `/search` | 继续兼容跳转或后续并入 Best Picks 搜索筛选。 |
| `/offers` | 继续跳转到 Deals。 |
| `/directory` | 继续跳转到 Best Picks。 |

## 5. 核心商业闭环

### 5.1 流量获取

Bes3 不应依赖用户主动逛首页。高意图流量应直接进入购买任务页。

主要入口：

| 入口 | 用户意图 | 落地页 |
| --- | --- | --- |
| Google SEO | best X for Y | 场景 pSEO 页 |
| Google SEO | X review | Review 页 |
| Google SEO | X vs Y | Compare 页 |
| Google SEO | best value X under $N | Deal 页 |
| AI 搜索 / GEO | 需要结构化答案 | BLUF + Top 3 + Schema 页面 |
| Reddit | 真实场景求推荐 | 场景页或 Top 3 页 |
| Newsletter | 回访和价格提醒 | Deal 页、商品页、watch price 页 |
| Shortlist 分享 | 犹豫用户回访 | Shortlist / Compare 页 |

### 5.2 站内决策

用户落地后，页面首屏必须压缩出明确判断：

```text
Should you buy it?
  -> Buy now
  -> Compare first
  -> Watch price
  -> Skip
  -> Researching
  -> Link unavailable
```

### 5.3 推广跳转

所有推广点击统一通过：

```text
/go/{productId}
```

该路由继续负责：

- 选择可用推广链接。
- 记录 merchant click。
- 处理断链或无目标 fallback。
- 跳转到 merchant destination。

新增要求：点击必须携带决策上下文。

### 5.4 数据回流

点击、无效 CTA、价格提醒、比较、跳出、缺货、断链等信号必须回流后台，用于决定：

- 哪些商品需要补推广链接。
- 哪些高证据商品不能变现。
- 哪些页面流量高但 CTA 弱。
- 哪些 deal 页面价格时机不佳。
- 哪些 pSEO 页面应暂停、强化或重新排序。

## 6. Purchase Decision System

### 6.1 目标

新增统一 `purchaseDecision` 派生模型，作为公开站购买页的核心展示逻辑。

它不替代现有共识分、价格价值、证据质量或风控逻辑，而是把这些系统信号翻译成用户可执行动作。

### 6.2 状态定义

| 状态 | 含义 | 主动作 |
| --- | --- | --- |
| `buy_now` | 证据、价格、链接、风险均达标。 | Check current price |
| `compare_first` | 产品可考虑，但应先对比替代品。 | Compare alternatives |
| `watch_price` | 产品可信，但当前价格不适合下单。 | Track price drop |
| `skip` | 证据或风险明确提示不应购买。 | See safer pick |
| `researching` | 数据不足，不能给购买判断。 | Browse category / get alert |
| `link_unavailable` | 有证据但无可用推广链接或购买路径。 | See available alternatives |

### 6.3 状态优先级

状态计算必须按阻塞优先级处理：

1. Critical risk 或低证据：`researching` / `skip`
2. 无有效推广链接：`link_unavailable`
3. 缺货或断链：`link_unavailable`
4. 价格明显 overpriced：`watch_price`
5. 竞品接近或争议高：`compare_first`
6. 全部达标：`buy_now`

### 6.4 buy_now 条件

`buy_now` 必须同时满足：

- 有可用推广链接。
- 非缺货。
- 非断链。
- 证据或商品数据达到现有 readiness 阈值。
- 当前价格不是明显 overpriced。
- 无 critical risk。
- 页面有足够信息解释为什么推荐。

### 6.5 输出结构

`purchaseDecision` 至少输出：

```text
state
headline
summary
primaryActionLabel
primaryActionHref
secondaryActionLabel
secondaryActionHref
proofBullets
riskBullets
priceLine
confidenceLine
trackingSource
ctaVariant
```

### 6.6 与现有 decisionReadiness 的关系

`decisionReadiness` 是系统内部信号，回答“这个对象是否具备支持购买判断的数据条件”。`purchaseDecision` 是用户可见决策，回答“用户现在应该采取什么动作”。

二者关系：

```text
Product / Evidence / Price / Link / Risk
  -> buildCommerceDecisionReadiness() 或 buildEvidenceDecisionReadiness()
  -> purchaseDecision 状态优先级和业务规则
  -> 用户可见 headline、CTA、proof bullets、risk bullets
```

必须避免直接把 `decisionReadiness.state = buy-ready` 显示为最终购买动作。原因：

- buy-ready 仍可能因为竞品接近而需要 `compare_first`。
- buy-ready 仍可能因为价格状态变差而降级为 `watch_price`。
- research-ready 可能因为无推广链接而成为 `link_unavailable`。
- not-ready 需要转换成用户能理解的 `researching` 或 `skip`。

建议新增核心文件：

```text
src/lib/purchase-decision.ts
```

核心接口：

```text
buildPurchaseDecision(input, context) -> PurchaseDecision
```

其中 `context` 至少支持：

```text
pageType
trackingSource
hasAlternatives
alternativeHref
userIntent
```

`purchaseDecision` 必须生成面向用户的文案，而不是只返回状态码。

### 6.7 状态映射规则

初版映射规则：

| 输入信号 | 输出状态 |
| --- | --- |
| no usable affiliate or merchant handoff | `link_unavailable` |
| out of stock or broken link | `link_unavailable` |
| evidence score low or critical risk | `skip` 或 `researching` |
| price entry status is `overpriced` | `watch_price` |
| readiness is buy-ready but strong comparable alternatives exist | `compare_first` |
| readiness is buy-ready and no blockers remain | `buy_now` |
| readiness is research-ready | `compare_first` 或 `researching` |
| readiness is not-ready | `researching` |

首期不要把阈值配置系统化；先集中在 `purchase-decision.ts` 中，待真实点击数据稳定后再迁移到后台配置。

## 7. 核心页面重构

### 7.1 首页

首页不承担主要成交，只承担三件事：

1. 解释 Bes3 的价值。
2. 引导用户进入 Best Picks。
3. 引导价格敏感用户进入 Deals。

首屏主 CTA：

```text
Find Best Picks
```

次 CTA：

```text
See Deals
```

首页不再强调 Evidence Matrix、Open Data 或 Tools。

### 7.2 Best Picks / 类目页

类目页首屏展示 Top 3：

| 推荐角色 | 含义 |
| --- | --- |
| Best Overall | 默认最稳选择。 |
| Best Value | 价格和证据组合最优。 |
| Best for Specific Need | 针对特定痛点最强。 |

完整 Evidence Matrix 放在第二屏之后，作为解释层。

### 7.3 商品页

商品页首屏从：

```text
Evidence Report
```

改为：

```text
Should you buy it?
```

首屏必须展示：

- purchase decision 状态。
- 当前价格。
- 买入窗口。
- 主 CTA。
- 3 条购买理由。
- 最多 2 条风险。
- FTC disclosure。

### 7.4 评论页

评论页不再只是文章阅读页。它应该是商品名搜索用户的购买落地页。

标题下方立即展示 `PurchaseDecisionCard`。正文保留证据、TOC、quote、structured data，但不先于购买判断。

### 7.5 Deal 页

Deal 页首屏必须回答：

```text
Is the buy window open?
```

而不是只解释 value score 公式。

`watch_price` 状态下主 CTA 是价格提醒，不是购买。

### 7.6 对比页

对比页必须给默认赢家。可以通过场景 lens 说明赢家何时反转，但不能让用户自己从表格推理。

## 8. 组件收敛

### 8.1 新增 PurchaseDecisionCard

`PurchaseDecisionCard` 是公开购买页的核心组件。

展示内容：

- 状态标签。
- 一句话购买结论。
- 当前价格和买入窗口。
- 主 CTA。
- 次 CTA。
- 证据数量或商品数据置信度。
- 风险提示。
- FTC disclosure。

### 8.2 降级 DecisionReadinessCard

`DecisionReadinessCard` 继续保留，但不再作为公开页首屏主组件。它可以用于：

- 二级解释。
- 后台展示。
- 调试 readiness。

### 8.3 嵌入 PriceValueBadge

`PriceValueBadge` 不再单独承担购买判断。它应该嵌入 `PurchaseDecisionCard`。

### 8.4 后置 HardcoreEvidenceMatrix

`HardcoreEvidenceMatrix` 从“首屏决策工具”改为“证据解释层”。它仍然保留完整表格、quote、price/value、out of stock fallback，但不作为用户第一眼看到的主判断。

### 8.5 Shortlist / Compare 降级

`ShortlistActionBar` 和 Compare 能力保留，但触发策略改变：

- `buy_now`：购买 CTA 优先，shortlist/compare 弱化。
- `compare_first`：compare 强化。
- `watch_price`：price alert 强化。
- `researching`：shortlist 或 alert 强化。

### 8.6 StickyMobileCta 跟随 purchaseDecision

移动端 sticky CTA 文案不能固定为 `Check Current Price`。它必须根据状态变化：

| 状态 | Sticky CTA |
| --- | --- |
| buy_now | Check current price |
| watch_price | Track price drop |
| compare_first | Compare alternatives |
| skip | See safer pick |
| researching | Browse category |
| link_unavailable | See available alternatives |

## 9. 流量获取闭环

### 9.1 SEO 页面策略

页面生成围绕购买任务，而不是功能模块。

优先页面类型：

- `best {category} for {painpoint}`
- `{product} review`
- `{product A} vs {product B}`
- `best value {category} under ${price}`
- `{category} buying guide for {scenario}`

### 9.2 GEO / AI 搜索策略

AI 搜索更容易引用结构清晰、答案直接、证据可追溯的页面。

每个核心页面应保持：

- BLUF。
- Top 3 表格。
- FAQ。
- Product / ItemList / AggregateRating Schema。
- Evidence quote。
- Creator attribution。
- llms.txt 可发现路径。

### 9.3 Reddit 分发策略

Reddit 不推矩阵、不推工具页、不推 Open Data。只推：

- 场景页。
- Top 3 结论。
- 一张截图或可复制表格。
- 明确购买建议。

回复话术应避免硬广：

```text
I built a small comparison from teardown/review evidence. 
For [scenario], these are the 3 picks I would actually compare first: [link].
```

### 9.4 回访策略

| 用户状态 | 回访机制 |
| --- | --- |
| watch_price | Price alert / newsletter |
| compare_first | Shortlist / compare share |
| researching | Category alert |
| link_unavailable | Alternative recommendation |

## 10. 转化追踪与指标

### 10.1 Tracking 要求

所有购买 CTA 必须携带：

```text
source
pageType
purchaseDecisionState
priceStatus
evidenceCount
ctaVariant
```

这些字段应同时服务两条链路：

1. CTA click 前的 `buyer_decision_events`，用于分析用户当时看到的页面状态。
2. `/go/{productId}` 的 `merchant_click_events`，用于分析最终推广跳转。

首期可以把扩展上下文存入现有事件 metadata，不新增核心表。

固定 tracking source：

| 来源 | trackingSource |
| --- | --- |
| 商品页购买卡 | `product-decision-card` |
| 评论页购买卡 | `review-decision-card` |
| Deal 页购买卡 | `deal-decision-card` |
| 矩阵行 CTA | `matrix-row-cta` |
| 移动 sticky CTA | `mobile-sticky-decision` |

### 10.2 主指标

```text
buy_ready_valid_affiliate_ctr =
  buy_ready_go_clicks / buy_ready_page_views
```

### 10.3 辅助指标

- 商品页 CTA CTR。
- 评论页 CTA CTR。
- Deal 页 CTA CTR。
- 移动 sticky CTA CTR。
- `compare_first -> /go` 转化率。
- `watch_price -> alert submit` 转化率。
- `price alert -> /go` 回访点击率。

### 10.4 质量指标

- 缺货点击率。
- 断链点击率。
- 无链接商品点击尝试。
- 低证据购买点击率。
- overpriced 强购买点击率。
- 高风险商品点击率。

### 10.5 运营指标

- buy-ready 页面数。
- buy-ready 页面比例。
- 高证据无链接商品数。
- 高搜索潜力无链接商品数。
- 商业阻塞修复时长。
- 可变现 pSEO 页面比例。

## 11. 后台运营闭环

### 11.1 Commercial Command Center

后台新增商业闭环面板，而不是泛数据看板。

核心卡片：

- buy-ready 页面数。
- 有效推广点击率。
- 高证据无链接商品。
- 缺货高分商品。
- 断链 CTA。
- overpriced 点击。
- 高流量低 CTA 页面。

### 11.2 Conversion Readiness

Products 列表增加 `Conversion readiness`：

| 状态 | 含义 |
| --- | --- |
| buy-ready | 可作为购买主推。 |
| blocked-no-link | 有证据但无推广链接。 |
| blocked-price | 价格缺失或不适合购买。 |
| blocked-evidence | 证据不足。 |
| blocked-stock | 缺货或断链。 |
| blocked-risk | 风险过高。 |

### 11.3 SEO Ops 商业状态

pSEO 页面增加商业状态：

| 状态 | 含义 |
| --- | --- |
| traffic-ready | 可获客，但不一定能转化。 |
| decision-ready | 可解释推荐，但购买路径未必完整。 |
| buy-ready | 可展示强购买 CTA。 |
| blocked | 不应作为购买页推广。 |

### 11.4 Risk Center 新风险

新增商业风险类型：

- `high_intent_no_cta`
- `high_score_no_link`
- `broken_go_path`
- `weak_evidence_buy_cta`
- `overpriced_buy_cta`
- `out_of_stock_buy_cta`

### 11.5 运营修复队列

后台自动生成修复优先级：

1. 高搜索潜力 + 高证据 + 无推广链接。
2. 高搜索潜力 + 有链接 + 缺价格。
3. 高流量页面 + CTA CTR 低。
4. 高点击商品 + 断链/缺货。
5. 高证据商品 + 无 review/deal/场景页。

首期执行必须按以下优先级推进，避免范围膨胀：

| 优先级 | 工作 | 说明 |
| --- | --- | --- |
| P0 | `purchaseDecision` 核心逻辑 | 没有它，页面只是在重排现有信号。 |
| P0 | `PurchaseDecisionCard` | 没有统一组件，商品页/评论页/deal 页会继续分散表达。 |
| P1 | 商品页和评论页接入 | 最接近购买意图，优先影响推广点击。 |
| P1 | Tracking context 扩展 | 没有上下文，无法验证 buy-ready CTR。 |
| P1 | 主导航收敛 | 降低入口噪音，但应在核心购买卡可用后上线。 |
| P2 | Deal/类目/对比页 Top 3 改造 | 扩大覆盖面。 |
| P2 | Commercial Command Center | 提升运营效率。 |
| P2 | 商业风险队列 | 系统化修复无法变现的高价值页面。 |

不建议首期做：

- 联盟订单级 ROI 接入。
- 大规模 A/B 测试框架。
- 将阈值全部后台配置化。
- 拆分 `commercial-loop.ts` 的大型重构。

这些都是合理方向，但不应阻塞 P0/P1。

## 13. 验收标准

### 13.1 用户体验验收

- 用户进入商品页或评论页首屏，30 秒内能判断买、比、等、跳过。
- 每个核心购买页首屏只有一个视觉主 CTA。
- 类目页和场景页首屏最多展示 3 个主推荐。
- 完整证据保留，但不抢首屏购买判断。
- 移动端 CTA 不遮挡内容，触控区域不小于 44px。

### 13.2 商业验收

- `buy_now` 页面 CTA 指向 `/go/{productId}`。
- 无链接商品不显示强购买 CTA。
- 缺货或断链商品不显示强购买 CTA。
- `watch_price` 状态主 CTA 是价格提醒。
- 所有购买 CTA 附近有 FTC disclosure。
- 后台能解释每个商品为什么不能进入 buy-ready。

### 13.3 数据验收

- CTA 点击记录 merchant click。
- CTA 点击记录 decision event。
- 点击 metadata 包含 purchase decision state。
- 后台能聚合 buy-ready 有效推广点击率。
- 风险中心能识别 broken、no-link、weak-evidence、overpriced CTA。

## 15. 假设与边界

1. 第一阶段不新增核心业务表，优先复用现有商品、证据、价格、事件和点击数据。
2. 订单和佣金归因后续通过 PartnerBoost/YeahPromos 报表导入单独规划。
3. 公开站面向普通购买用户，不面向数据研究者。
4. Open Data 保留，但降级为 Trust/footer/API 场景。
5. 商业化影响 CTA 展示和运营优先级，不影响证据分和推荐结论。
6. 首页承担导流和解释，不承担主要成交。
7. 成交主要发生在商品页、评论页、deal 页、场景页和对比页。
8. Shortlist、Compare、Tools 保留，但不与高意图购买 CTA 竞争。

## 16. 最终形态

Bes3 的最终公开体验应从“这里有很多证据和工具”转变为：

```text
Tell me what you need.
Here are the 3 picks that matter.
This is the one to buy now.
Here is why.
Here is the risk.
Check the live merchant price here.
```

最终后台体验应从“管理商品和内容”转变为：

```text
Which pages can make money?
Which good products cannot convert?
Which high-intent pages lack a safe CTA?
Which risks are blocking buy-ready status?
What should ops fix next?
```

这就是 Bes3 的核心商业闭环：用证据获取信任，用决策降低难度，用推广链接完成变现，用数据回流持续提高下一轮转化。
