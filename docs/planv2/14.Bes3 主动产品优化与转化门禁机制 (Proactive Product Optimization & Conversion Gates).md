# Bes3 主动产品优化与转化门禁机制

> 本文是 PlanV2 的主动优化补充机制。若与旧文档冲突，以本文和 `13.Bes3 购买决策与推广转化闭环重构方案` 为准。

## 1. 背景

Bes3 的目标不是“页面可访问”，而是让高意图用户更快完成可信购买决策，并在买入状态下点击可归因的联盟推广链接。之前的问题说明，仅靠人工肉眼浏览和“按钮存在”检查不足以发现真实转化阻塞，例如：

- Web/平板断点首屏被商品图占据，购买判断和 CTA 掉到首屏以下。
- CTA 虽然存在，但位置过低，用户需要先阅读过多解释。
- 验证关注页面不报错，却没有量化“首屏是否回答现在买吗、为什么、点哪里”。
- SEO/GEO、证据、联盟跳转和转化事件没有被统一纳入同一条门禁。

因此，Bes3 必须建立“主动发现问题”的机制：每次改动都先定义可量化的产品结果，再用脚本和复盘制度拦截退化。

## 2. 北极星

核心北极星：

```text
高意图访问 -> 首屏购买判断 -> 信任证明 -> /go 佣金跳转 -> 数据回流 -> 后台修复下一批阻塞
```

核心指标：

| 指标 | 目标 | 失败信号 |
| --- | --- | --- |
| Buy-ready CTA visibility | 关键断点首屏可见 | CTA 在首屏以下、被图/长文挤压。 |
| Valid affiliate handoff | `buy_now` CTA 只走 `/go`，最终到可佣金链接 | 手写外链、无 `tag`/联盟参数、断链。 |
| Decision clarity | 首屏同时回答“买不买、为什么、点哪里、风险是什么” | 首屏先展示方法论、长表格、裸图片。 |
| SEO/GEO answer quality | 页面有可抓取 BLUF、schema、开放 JSON、证据入口 | AI/搜索只能读到营销文案或空推荐。 |
| Conversion learning loop | 点击事件带 decision metadata | 后台只看到总点击，无法知道阻塞原因。 |

## 3. 主动优化闭环

### 3.1 每次改动前

任何影响公开页面、购买决策、联盟跳转、SEO/GEO、内容生成、商品数据的改动，都必须先回答：

| 问题 | 必须有明确答案 |
| --- | --- |
| 用户任务是什么？ | 搜索商品、比较、找好价、确认是否购买、查看证据。 |
| 首屏唯一主动作是什么？ | `Check current price`、`Compare alternatives`、`Track price drop` 等。 |
| 当前状态是否允许购买 CTA？ | 只有佣金链接、有效 offer、价格、证据/数据信心满足时才可强化 `/go`。 |
| 哪些断点最容易坏？ | 至少覆盖 `390 / 768 / 1024 / 1100 / 1279 / 1280 / 1440`。 |
| SEO/GEO 是否仍可读？ | 页面 HTML、schema、开放 JSON、证据入口必须保留。 |

### 3.2 开发中

开发过程中不能只证明“页面没坏”，必须证明“转化路径更短、更可信”：

- 首屏信息顺序必须是：购买判断 -> 价格/信心 -> 主 CTA -> 核心证据 -> 风险/方法论。
- 商品图、长描述、完整证据矩阵、Open Data、机器 payload 不能压过购买判断。
- `buy_now` 状态主 CTA 必须统一走 `/go/{productId}`，不能直接写外部商家链接。
- 非 `buy_now` 状态不能走 `/go` 强推购买。
- 风险、FTC disclosure、佣金中立说明必须存在，但不能抢主 CTA。
- 所有改动都必须考虑 Web、平板、移动，不允许只优化移动端或只优化 1440 桌面。
- `PrimaryCta` 和 `StickyMobileCta` 必须通过 `isExternalCtaHref` 区分真实商家/外部出站与页面内部操作；只有 `/go/` 或 `http(s)` 出站才允许新开标签、显示出站箭头并使用出站语义。
- 页面内部锚点、分类页、价格提醒、证据回看等操作必须保持当前标签页，并记录为购买决策操作，而不是误记为 `merchant_cta_click`。
- 动态审计必须拦截 `visible /go CTA must open safely in a new tab`、`internal operation link should stay in current tab`、`final decision recovery merchant CTA must open safely in a new tab` 这三类链接语义错误。
- sticky mobile CTA can collapse：移动端 sticky CTA 下滑阅读时必须折叠成小把手，不得长期覆盖底部内容、表单或 Open Data 链接。
- 页面最后一个公开内容区必须为移动 sticky CTA 预留底部安全空间，例如 `pb-36 sm:px-6 sm:pb-14`，避免最终操作被固定底栏遮住。
- 商品页读到底部后必须有 `final-decision-recovery`，把用户从 Product Facts / Open Data 明确带回购买判断、offer 复核或合规的 `/go` 推广 CTA，不能让页面以机器 payload 作为最后一步结束。

### 3.3 发布前

发布前必须运行：

```bash
npm run product:strategy-gates
npm run product:optimization-gates
npm run product:conversion-ux-audit
npm run planv2:check-purchase-decision
npm run planv2:check-business
npm run pseo:check-recommendation-quality
npm run build
```

`product:optimization-gates` 是专门防止产品体验退化的硬门禁。它必须拦截：

- 产品页没有首屏购买判断。
- 商品图在中小 Web 断点优先于购买决策。
- compact 购买卡不是 CTA-first。
- 商品页主 CTA 没有 `/go`。
- `/go` 路由没有佣金链接校验、fallback、点击记录。
- SEO/GEO 入口缺少开放 JSON、schema、sitemap、`llms.txt`。
- release preflight 没有包含产品优化门禁。

`product:conversion-ux-audit` 是动态浏览器审计。它必须真实打开商品页，在 `390 / 768 / 1024 / 1100 / 1279 / 1280 / 1440` 断点检查：

- `h1`、主 `/go` CTA、证据入口是否在首屏阈值内。
- 1024 以下断点商品图不能先于 CTA。
- 1024-1279 Web 窄屏必须进入双栏过渡布局，不能停留在移动端纵向堆叠。
- `Decision Notes` 在 Web 双栏内容区必须跨列，不能只占左列并留下右侧空白。
- 商品页必须提供可见的操作脚手架：`decision-shortcuts`、`decision-path`、`buy-decision`、`current-offer` 和证据区二次 CTA。
- 商品页底部必须提供 `data-product-ux="final-decision-recovery"`，否则审计报 `final decision recovery is missing`。
- `PrimaryCta` 必须只让真实商家/外部出站新开标签；内部操作不能带出站箭头，不能记成 merchant exit。
- 可见 `/go` CTA 和 final decision recovery merchant CTA 必须 `_blank` 且带 `noopener noreferrer`；`#buy-decision`、`#current-offer`、`#decision-notes`、`#product-facts` 等内部操作必须当前页打开。
- sticky mobile CTA can collapse，且移动端最终内容必须留出足够底部空间。
- 页面无横向溢出。
- console error/warning 默认视为失败。
- 页面 HTML 保留 `application/ld+json`、开放商品/offer JSON、`decision-notes`。
- 可见 `/go` CTA 最终重定向到 commissionable merchant URL。

生产发布前可通过环境变量运行：

```bash
BES3_PREFLIGHT_RUN_PRODUCT_UX_AUDIT=true npm run ops:preflight-release
```

### 3.4 发布后

每次生产更新后，必须做真实线上验证：

- 选 1 个 buy-ready 商品页。
- 选 1 个 compare/watch/blocked 商品页或场景页。
- 在 `390 / 1024 / 1440` 下测首屏。
- 检查 console error/warning。
- 检查 `/go` 307 location 是可佣金链接。
- 检查开放 JSON 与页面显示一致。
- 记录发现的问题为 Beads，不允许写散落 TODO。

## 4. 固定断点矩阵

| 断点 | 代表场景 | 必查 |
| --- | --- | --- |
| 390x844 | iPhone 主流移动端 | 标题、价格、主 CTA 首屏可见；sticky CTA 不挡内容。 |
| 768x1024 | 平板竖屏 | 决策优先于图片；无横向滚动。 |
| 1024x768 | Web/平板临界区 | 不能让商品图占满首屏；CTA 必须首屏可见。 |
| 1100x900 | Web 窄屏/小笔记本 | 必须进入 Web 双栏过渡布局；图片和购买卡不能掉到首屏下方。 |
| 1279x900 | `xl` 前一像素 | 不能停留在移动端纵向堆叠；和 1280 的布局切换必须连续。 |
| 1280x900 | 笔记本 Web | 三栏/双栏布局必须可点击，不挤压 CTA。 |
| 1440x1000 | 标准桌面 | 商品身份、图、购买决策、证据入口同屏。 |

## 5. 页面级硬标准

### 5.1 商品页

首屏必须包含：

- `Should you buy it?`
- 简短商品名，不是完整 SEO 长标题。
- 当前价格。
- 买入状态或比较/等待/跳过状态。
- 主 CTA。
- 证据入口。
- FTC/佣金 disclosure。

首屏不能出现：

- 商品图排在购买判断之前，占满 1024 宽首屏。
- Web 端 1024-1279 仍使用移动端纵向堆叠，浏览器拉宽时页面不跟随自适应。
- Web 双栏过渡布局只移动了图片，却没有用 `lg:row-start-1` 把购买决策卡固定到首屏右列。
- `Decision Notes` 作为两列 grid 的第三个子项只占左列，右侧留下大面积空白。
- 页面只有阅读内容，没有快捷锚点、3 步购买路径、证据区下一步 CTA，用户看完证据后不知道如何回到购买判断。
- Product Facts / Open Data 作为页面终点，缺少 `final-decision-recovery` 导致用户读完后没有下一步。
- 移动 sticky CTA 只能向下滑动时折叠，不允许覆盖页面底部最终内容；`product-facts` 等末尾内容必须保留移动端底部安全留白。
- 内部操作链接被 `target="_blank"` 新开页、显示出站箭头或被记为 `merchant_cta_click`。
- 完整机器 payload 默认展开。
- 无佣金链接商品显示强购买 CTA。
- 无评测/无证据商品进入评测页并对用户公开为购买推荐。

### 5.2 Review / Deal / Compare / pSEO 页面

必须遵守同一条规则：

```text
先给结论，再给证据；先给行动，再给方法论。
```

| 页面 | 首屏主任务 |
| --- | --- |
| Review | 这款现在能不能买。 |
| Deal | 现在是不是好价。 |
| Compare | 默认赢家是谁，什么条件下反转。 |
| pSEO 场景页 | 当前 Top 1-3 和信心边界。 |
| Category | 当前最值得买的 1-3 个选择。 |

## 6. 数据与商业门禁

商品进入公开购买路径前必须满足：

| 条件 | 不满足时 |
| --- | --- |
| 有 commissionable affiliate URL | 不展示购买 CTA，不进入买入推荐。 |
| 有 offer 或当前价格 | 不强化 checkout，进入 compare/watch/research。 |
| 有证据或足够商品事实 | 不生成“评测推荐页”。 |
| `/go` 可跳转并记录 metadata | 阻塞发布。 |
| 价格/库存/链接未过期或有 freshness 提示 | 降级为 watch/research。 |

## 7. SEO/GEO 同步优化

主动优化不能只看人类 UI，也必须看搜索引擎和 AI：

- 页面 HTML 中必须有明确购买判断，而不是只靠客户端渲染。
- Product/FAQ/Breadcrumb schema 必须和页面结论一致。
- `llms.txt`、open commerce API、sitemap 必须指向可验证页面。
- pSEO 页面如果证据不足，必须 noindex 或显示质量边界。
- AI 可读 payload 可以存在，但默认折叠，不能干扰用户转化。

## 8. Beads 执行制度

主动优化发现的问题必须进入 Beads：

- P0：购买 CTA 断链、非佣金跳转、无佣金商品强推购买、生产构建失败。
- P1：关键断点首屏 CTA 不可见、SEO/GEO 页面错误索引、证据不足却公开推荐。
- P2：CTA 位置偏低、文案不清、风险说明过重、开放 JSON 不完整。
- P3：视觉 polish、低频断点、辅助动效。

每次主动巡检输出：

```text
发现的问题 -> 对应 Bead -> 修复提交 -> 复验结果 -> 关闭 Bead
```

## 9. 最低可执行清单

每次我作为编码代理处理 Bes3 产品体验问题时，必须主动执行：

1. 读取相关 PlanV2 新文档。
2. 明确本次改动影响的用户任务和转化路径。
3. 覆盖 Web、平板、移动断点。
4. 检查首屏 CTA 坐标，而不是只看 DOM 是否存在。
5. 验证 `/go` 的最终 location 是否可佣金。
6. 检查 console warning/error。
7. 跑 `product:optimization-gates`。
8. 把新发现的问题创建/关联 Bead。
9. 提交、推送、关闭 Bead、`bd dolt push`。

这套机制的目标是让 Bes3 主动发现“用户为什么还不敢点购买链接”，而不是等用户指出页面哪里不合理。
