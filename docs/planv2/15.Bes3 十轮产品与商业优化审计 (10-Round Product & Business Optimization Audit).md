# Bes3 十轮产品与商业优化审计

> 本文把“继续优化产品”落到可执行产品决策。它不是散点 TODO，而是当前 Bes3 的定位、用户、功能、架构、盈利、体验和 pSEO 自动化的十轮审计结论。

## 成功标准

Bes3 必须被用户和运营者理解为一个“买不买决策引擎”，不是泛评测站、优惠券站或纯 AI 内容站。

北极星链路：

```text
高意图搜索 / 站内意图 -> 商品或场景页 -> 买 / 比 / 等 / 跳过 -> 可审计证据 -> 合规 /go 出站 -> 点击与阻塞回流 -> 后台修复 -> 下一批 pSEO 页面
```

硬约束：

- 定位必须一句话说清：Bes3 用真实评测证据、价格窗口和可佣金商家路径，把复杂商品选择压缩成 buy / compare / wait / skip。
- 用户画像必须围绕高焦虑购买任务，而不是泛流量人群。
- 商业模式必须 buyer-first：联盟转化是收入来源，但不允许改变推荐排序。
- UX 必须首屏先回答“现在该做什么”，再解释方法论。
- 自动化 pSEO 必须由意图、证据、价格、链接健康共同驱动；证据不足就 noindex 或降级。
- 系统架构必须服务闭环修复，而不是只生产页面。

## Round 1 - 产品定位

当前判断：定位已经从“best picks”收敛到购买决策，但公开叙事还需要反复强调“决策引擎”而不是普通内容站。

决策：

- Bes3 的公开定位是 `Buyer decision engine for hard-to-judge products`。
- 首页、About、Trust、Open Data 必须共同解释同一件事：证据、价格、风险、商家路径共同决定下一步。
- 不再把旧 commerce API、泛搜索、泛评测作为产品中心。

## Round 2 - 用户画像

核心用户不是低意图闲逛者，而是已经接近购买、但因为证据冲突或价格不确定而犹豫的人。

三类首要画像：

- Anxious buyer：担心买错，想知道“现在能不能买”。
- Comparison buyer：已有 2-4 个候选，想知道默认赢家和反转条件。
- Deal-timing buyer：认可产品，但需要判断现在买还是等降价。

二级画像：

- Evidence skeptic：不信营销规格，需要看真实评测、引用和风险。
- AI / crawler consumer：通过搜索、AI agent 或 open API 读取机器可验证的结论。
- Operator：在后台修复链接、证据、价格、风险和 pSEO 阻塞。

## Round 3 - 真实痛点

Bes3 必须解决的痛点：

- 商品规格无法回答真实场景表现。
- 评测内容分散，用户无法快速比较证据强度。
- 好价、库存和佣金链接状态与推荐结论割裂。
- 许多 SEO 页面为了收录而给出假确定性。
- 运营者不知道哪些页面有流量但不能转化。

产品承诺：

- 有证据才给强推荐。
- 有价格上下文才说是不是好价。
- 有有效 `/go` 才强化购买 CTA。
- 证据薄、链接坏、价格风险高时必须降级为 compare / wait / research / skip。

## Round 4 - 业务功能

当前功能应被组织为五个业务系统：

- Decision surface：首页、分类、商品、review、deal、compare、pSEO 场景页都输出 buy / compare / wait / skip。
- Evidence engine：YouTube / creator evidence、风险、引用、共识评分、反馈纠偏。
- Price-value engine：当前价、历史低价、90 天均价、价格提醒、buy window。
- Commercial loop：affiliate sync、`/go` 出站、merchant click metadata、CTR、修复队列。
- Growth automation：taxonomy、intent mining、scenario pSEO、sitemap、llms.txt、open APIs、indexing。

## Round 5 - 系统架构

架构判断：代码已经具备 PlanV2 闭环，但必须在文档和公开页面中讲清楚“为什么这些模块存在”。

目标架构：

```text
Intent signals -> Taxonomy tags -> Product candidates -> Evidence extraction
-> Consensus + risk -> Price-value -> Purchase decision
-> Public page / open API / schema -> Merchant handoff
-> Decision events + merchant clicks -> Admin repair queue
-> pSEO refresh / indexing / syndication
```

架构原则：

- 数据层支持 SQLite / Postgres，但产品逻辑不能依赖本地手工数据。
- 页面必须 server-render 关键结论，不能只靠客户端组件表达购买判断。
- 公开 API 和 schema 必须与页面可见结论一致。
- 后台不是 CMS，而是商业闭环修复系统。

## Round 6 - 盈利模式

主要收入：联盟佣金。

可扩展收入：

- Price alert 或 buying assistant 的订阅提醒。
- B2B open commerce / evidence API。
- 品类研究报告或数据授权。
- 商家质量改进反馈，但不得购买排序。

红线：

- 佣金率不参与公共推荐排序。
- 无有效佣金链接不能显示强购买 CTA。
- 有商业出站必须明确 disclosure。
- 推荐结论必须能被证据、价格和风险解释。

## Round 7 - 用户体验

UX 标准：先行动，后解释。

每个高意图页面首屏必须尽量回答：

- 现在买、比较、等价、还是跳过？
- 为什么？
- 价格 / 证据 / 风险信心如何？
- 下一步点哪里？
- 如果不买，替代路径是什么？

移动端原则：

- CTA 必须是 44px 以上可点击目标。
- sticky CTA 不能遮挡底部内容。
- 方法论、开放 JSON、完整证据矩阵不得压过主决策。

## Round 8 - 自动化 pSEO

pSEO 的价值不是批量生成页面，而是把长尾问题映射到可验证决策。

索引前必须满足：

- 有足够 eligible products。
- 有独立证据来源。
- 有价格和商家路径。
- 有 FAQ / schema / open payload。
- 有质量边界；证据不足必须 noindex 或明确 researching。

自动化循环：

```text
Search/log/import signals -> pending taxonomy tags -> promoted intents
-> scenario/value pSEO pages -> render audit -> indexing/syndication
-> impressions/clicks/merchant exits -> admin repair queue
```

## Round 9 - 运营与风控

运营目标不是“发更多页”，而是提高可转化且可信的页面占比。

后台必须优先暴露：

- Buy-ready products。
- High-intent pages with no CTA。
- High-score products with no affiliate link。
- Broken `/go` or non-commissionable paths。
- Weak evidence buy CTAs。
- Overpriced or out-of-stock buy CTAs。
- pSEO pages blocked by evidence, price, link, or quality gates。

## Round 10 - 下一阶段产品策略

短期聚焦：

- 明确 public positioning：所有核心入口都说“买 / 比 / 等 / 跳过”。
- 强化 persona pathway：用户按任务进入，而不是按站点栏目猜。
- 让 Trust / Data 页面解释商业闭环和 pSEO 质量门禁。
- 把 strategy gate 纳入 release preflight。

中期聚焦：

- 增加意图级漏斗看板：scenario view -> decision view -> merchant exit。
- 增加页面级 pSEO reason codes：why indexable / why noindex。
- 增加 persona-based onboarding：anxious buyer、comparison buyer、deal-timing buyer。
- 对高价值品类做更严格的 evidence source diversity。

长期聚焦：

- 从 affiliate site 演进为 machine-readable commerce decision network。
- 对 AI agents 输出可验证 open commerce objects。
- 对人类用户保持快速、透明、少废话的购买决策体验。

## 本轮落地项

- 将 strategy gate 放入 release preflight，防止定位和商业闭环叙事退化。
